## 1. 目标与范围

在现有 SKU 采集链路中评估匿名公开读取能力；遇到风控时明确停止或等待恢复，不以删除 Cookie 作为保证可用的方案。只关注真实 SKU 规格组合，不需要详情正文。建议同时停止独立详情图请求，但详情图是否保留需确认。

## 3. 必须先确认的业务定义

### 3.1 无 Cookie 的两种含义

- A：不导入账号 Cookie。使用独立访客会话，可以接受网站正常下发的匿名 Cookie。它不是严格零 Cookie。
- B：全程不发送 Cookie。初次请求、允许的重定向及后续请求均不得携带 Cookie；响应下发的 Cookie 不得在后续请求复用。空 CookieJar 初始化本身不足以保证这一点。

建议先验证 A；若业务明确要求 B，则以 B 为准，不能偷偷退回 A 或带账号模式。当前只提出选择，不提前实现。

### 3.2 规格表范围

- 基础矩阵：SKU ID、规格维度、规格值、真实组合。
- 扩展字段：规格图、SKU 价格、阶梯价、库存。

先确认基础矩阵是否足够。价格或库存缺失不能用商品最低价、0 或其他 SKU 的字段填补；当前模型没有库存字段。

### 3.3 内容范围

建议不请求描述正文及详情长图；保留商品主 HTML 中已有的 SKU 及必要规格字段，不额外下载图片。

“不需要详情页内容”若表示连商品主 HTML 都不能请求，则现有解析路线不成立，必须另行确认有权限、可用的结构化数据来源，不能承诺当前方案可行。

## 4. 风控场景下的建议行为

1. 先将匿名采集做成显式模式，独立验证是否能读取正常公开商品数据，而不是立即开发自动切换。
2. 无活动 Cookie 不等于被风控；匿名模式可以在未受限且平台允许公开访问的情况下正常提交任务。
3. 401、登录跳转或会话失效：结束当前任务，明确返回需要登录/会话不可用；是否允许用户另行选择公开匿名读取，需结合平台访问要求和当前保护状态判断。
4. 403、429、挑战页：保留原有暂停或冷却处理，不立即换会话反复请求，不伪装为正常成功。
5. 限制解除、冷却结束或用户完成必要验证后，再由用户明确选择允许的采集模式。
6. 匿名返回正常商品 HTML：复用解析器；没有规格数据时返回来源不适用或缺失，不生成推测规格。
7. 本轮不新增复杂自动重试、备用浏览器、跨任务恢复机制；只复用现有任务独立执行结构。

结论：无账号 Cookie 可以减少对账号会话的依赖，但不证明网络、设备、访问频率等层面的限制会消失。本次不判断实际触发风控的原因。

## 5. 规格表完整性如何判断

### 5.1 现有数据来源

- 主来源：交易模型中的 `tradeModel.skuMap` 和 `offerDetail.skuProps`。用真实 SKU 行建立组合，不对颜色与尺码做笛卡尔积。
- 备用来源：已确认归属当前商品的 `pieceWeightScaleInfo`。可获得部分 SKU/位置规格值，规格名称可能无法确认；不能仅凭它证明全部 SKU。
- 当前两个来源不是无条件合并。出现冲突或身份不明时不能为了增加数量而合并。
- V2 的选项来自最终有效 SKU，不能用它反过来证明原始全部规格选项都已覆盖。
- `size_summary` 是派生汇总，不是原始完整规格矩阵；完整表以真实 `skus` 及规格引用为准。

### 5.2 分开两个层级

1. 响应解析覆盖：本次响应中可识别的源行，有多少成功转为有效 SKU；源行数、唯一 SKU 数、无效/冲突数分别记录。没有丢行只证明本响应解析完整。
2. 商品全量覆盖：是否包含平台该商品在目标销售范围内的全部 SKU。没有可信总量或完整参考集合，就保持 unknown。

建议只添加最少诊断字段：采集模式、数据来源、源行数、有效唯一 SKU 数、无效/冲突行数；复用原有 warnings 和 completeness。具体命名以实施时现有模型为准。

### 5.3 验证方法

在得到允许后，选择少量有代表性的商品：单规格、颜色×尺码、多规格，以及有缺货/不可售选项的商品（若业务要求这些也包含在内）。

- 同一商品、相近时间，对比匿名结果与人工确认或合法授权来源的 SKU ID 集合。
- 同时核对维度名称、值、组合对应；不能只比数量。
- 参考数据若本身不完整，只能证明两份样本一致，不能标记商品全量完整。
- 分别记录获取成功率、响应解析覆盖情况、参考集合匹配情况，不将三者合并为一个“成功”。
- 不为制造测试条件而主动触发风控；受限响应可先用已有脱敏样本验证判断逻辑。

只有一个商品的独立可信全量基准匹配成功，才可称该商品该时点已核验；不可扩展成所有商品都完整。

## 7. 验收与终止条件

- 不导入 Cookie 的模式确实不读取用户账号凭证；严格模式的所有请求均无 Cookie 头。
- 正常页面可复用现有解析输出真实 SKU；缺失数据如实为空或未知。
- 停止独立描述请求，减少与本目标无关的请求。
- 不将 HTTP 200、非空 SKU、两来源数量相等或颜色×尺码数量相等作为商品全量证明。
- 匿名仍遇到访问限制即停止该次采集；不能保证获取时明确报告，必要时另行评估官方授权数据或供应商提供的数据。
