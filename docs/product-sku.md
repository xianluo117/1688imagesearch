# 独立1688 SKU模块使用说明

调用方接入请查看[获取商家ID与SKU ID API文档](merchant-sku-api.md)，包含鉴权、请求/响应示例、字段说明及错误处理。

最新规格图片扩展：按用户新要求，新增[去重规格图片列表](../src/api/sku_schemas.py:31)，仅返回URL，不下载图片。每个最终SKU使用的规格选项保留一条记录，同色不同尺码不会重复颜色图片；缺失、不安全或冲突地址返回空值，不用主图替代。此前“不提取图片”记录为历史范围，商品主图行为未变。商品844515661443实测24个SKU、3条非空颜色图片URL、8条尺码空值，87项离线测试通过；图片可访问性未下载验证。接口需重启后加载，详细契约见上述API文档第3.3节。

## 1. 范围

输入标准1688详情链接，请求详情HTML，输出商品ID、SKU ID、规格位置和值、规格名、商品主图及状态。可使用命令行，或第7节新增的独立HTTP接口。

- HTTP接口复用服务器已有Cookie和查询鉴权，不修改图搜流程，不创建图搜任务或新数据库表，不调用MTOP，不启用浏览器兜底。
- 命令行只读取明确传入的Cookie路径；HTTP接口读取服务器当前激活版本，不需要调用方再次上传Cookie。
- 没有真实Cookie，不代表已成功在线采集。目标商品772946834568仍待实测。
- 已验证交易模型支持规格名称及位置，逐行核对规格定义，不推断颜色、尺码。旧重量表来源仍可能缺少规格名称。
- 主图仅接受唯一且绑定当前商品地址的Open Graph元数据。此规则只经过合成样例测试，未确认目标页面提供这些元数据。

## 3. 运行

在项目根目录、已安装[项目依赖](../requirements.txt)的Python环境执行。PowerShell中先将控制台输出编码和Python UTF-8模式设为UTF-8。

调用格式：python ＋ [命令行入口](../src/fetch_1688_sku.py) ＋以下参数。

| 参数 | 用法 |
|---|---|
| --url | 必填，例如 "https://detail.1688.com/offer/772946834568.html" |
| --cookie-file | 必填，已有Cookie文件的实际路径；建议加双引号 |
| --output | 可选，结果JSON文件路径；省略则输出到控制台。父目录须存在，会覆盖已有文件，不可与Cookie文件相同 |
| --timeout | 每次请求超时秒数，默认20，范围大于0且不超过120 |
| --retries | 网络失败和临时服务错误重试次数，默认1，允许0至2 |
| --help | 查看参数说明，不采集 |

支持标准HTTP输入，统一规范化为HTTPS；删除查询参数与片段。只接受详情域名和数字商品路径，拒绝用户信息、显式端口和非详情路径。

Cookie格式沿用[现有加载器](../src/image_search/cookies.py)：导出的记录数组、包装对象、名称到值映射或Cookie头文本。推荐记录数组，避免丢失路径、有效期与安全属性。不要求MTOP Token。过期或不适用域的记录会被过滤，路径和安全属性交给CookieJar匹配；无可用记录则初始化失败。

## 4. 结果与退出码

[结果结构](../src/product_sku/models.py:23)包含商品ID、规范链接、来源、状态、原因、主图、SKU数组、数量、警告和完整性。SKU ID使用字符串。规格保留数字位置和原始字段；例如第一、第三位置有值时，第二位置仍保留为空。

| 状态 | 含义 | 退出码 |
|---|---|---|
| partial_success | 至少有一条有效SKU；缺少可靠规格名、主图或完整性证明 | 0 |
| success | 预留完整成功状态；当前解析器不返回，不承诺全部SKU | 0 |
| access_restricted | 风控挑战、403、429或禁止的重定向 | 1 |
| login_required | 登录跳转、明确登录表单或401 | 1 |
| source_not_applicable | 当前商品字段缺失或空数组，由原因字段区分 | 1 |
| parse_failed | 格式错误、归属不明、无有效SKU、超出限制等 | 1 |
| network_failed | 有限重试耗尽或异常HTTP状态 | 1 |
| 参数、初始化、内部错误或输出失败 | 标准错误仅输出固定说明，不输出异常原文 | 2 |

有效SKU必须同时包含有效ID与至少一个非空字符串规格值。拒绝浮点、布尔ID；重复一致记录合并，同一ID规格冲突时移除该ID并告警。不会根据SKU顺序推断规格名称或颜色图。

## 5. 解析边界

- 只解码脚本中的完整JSON对象、数组或JSON字符串，不执行脚本，不做整页反转义。非JSON的JavaScript对象及单引号字符串不保证支持。
- 使用明确商品身份字段建立归属；排除推荐分支、外商品；匿名列表及不明确实体不继承归属。不以页面URL直接认定所有数组属于当前商品。
- 拒绝重复JSON键。无法验证归属时宁可报告失败，不盲目收集整页SKU。
- 上限：响应4 MiB，结构深度32，JSON候选256，节点/行100000，规格位置32。解码后的文本也受大小限制。
- 手工最多两次重定向，仅允许同商品HTTPS规范详情地址；不会请求登录域、外域或挑战地址。
- 默认每次请求20秒，最多一次网络重试。429、403和已识别访问限制不重试。
- 每次响应均关闭，自建会话关闭；借入会话不关闭。借入会话必须是专用干净会话，客户端会替换其CookieJar，不适合借用正在使用的图搜会话。
- 默认自建会话使用Chrome模拟，不继承图搜来源头，禁用环境代理继承。Chrome模拟不保证与Cookie来源浏览器完全一致。
- UTF-8优先；仅在响应头明确指定GBK/GB2312时尝试相应兼容解码，不静默替换乱码。
- 不保存整页、Cookie、签名或异常原文；风险跳转参数不会进入结果。

## 7. HTTP API调用

### 7.1 地址和鉴权

- 网站：https://1688imagesearch.xiaoc-ai.com
- 请求：POST https://1688imagesearch.xiaoc-ai.com/api/v1/product-skus
- 请求头：Content-Type 为 application/json；X-API-Key 为现有搜索密钥，对应服务器 SEARCH_API_KEY，不能使用Cookie上传密钥。
- 只需提交字符串字段 [`product_url`](../src/api/sku_schemas.py:12)，不接受额外字段，不接收Cookie或图搜任务ID。
- 每次查询读取服务器已激活Cookie版本，使用独立会话；不修改服务器Cookie记录，不把Cookie放进响应。已有Cookie可用时无需重新上传。

### 7.2 目标898728774563调用示例

在本地PowerShell中运行。先由用户在本地安全配置 SEARCH_API_KEY 环境变量；以下示例不包含真实密钥，不会读取服务器私密文件。请求契约见 [`ProductSkuRequest`](../src/api/sku_schemas.py:9)，鉴权见 [`_authorize()`](../src/api/sku.py:13)。

```powershell
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
$OutputEncoding = [Console]::OutputEncoding
$body = @{ product_url = 'https://detail.1688.com/offer/898728774563.html' } | ConvertTo-Json -Compress
Invoke-RestMethod -Method Post `
  -Uri 'https://1688imagesearch.xiaoc-ai.com/api/v1/product-skus' `
  -Headers @{ 'X-API-Key' = $env:SEARCH_API_KEY } `
  -ContentType 'application/json' -Body $body -TimeoutSec 110 |
  ConvertTo-Json -Depth 12
```

这是调用示例，不是该商品在线成功记录。非2xx响应需由调用方读取HTTP错误响应体，不能只显示通用网络错误。

### 7.3 响应和错误

有分类结果时直接返回 [`ProductSkuResponse`](../src/api/sku_schemas.py:15)，不包任务对象、不返回轮询ID。包含商品ID、规范链接、来源、状态、原因、主图、SKU数组、SKU数量、警告和完整性；结构沿用[独立结果模型](../src/product_sku/models.py:21)。HTTP状态映射见[路由](../src/api/sku.py:63)。

| HTTP | 场景 | 响应处理 |
|---|---|---|
| 200 | success、partial_success | 读取SKU及警告；当前真实解析器只产生部分成功，不保证全部SKU |
| 200 | source_not_applicable | 当前来源缺少字段或字段为空；这是有分类的查询结果，不表示已获取SKU |
| 401 | 查询密钥缺失或错误 | detail中返回固定错误码 INVALID_API_KEY |
| 422 | 非法链接、缺少字段、类型错误、额外字段 | 修正请求；不发起详情请求 |
| 429 | 并发已满 | detail错误码 SKU_BUSY；稍后重试，不进入等待队列 |
| 502 | access_restricted、parse_failed、network_failed | 保留完整分类结果、原因及警告；风控不自动重试 |
| 502 | 未预期异常或结果结构异常 | detail错误码 SKU_QUERY_FAILED；不回显异常原文 |
| 503 | 无激活Cookie、密文损坏、无适用Cookie | detail错误码 COOKIE_UNAVAILABLE；由管理员检查已有会话 |
| 503 | login_required | 保留分类结果；服务器会话被上游要求登录，不是查询密钥错误 |
| 503 | 服务关闭中 | detail错误码 SKU_SERVICE_STOPPING |
| 504 | 请求等待超时 | detail错误码 SKU_QUERY_TIMEOUT；后台线程结束前仍占槽 |

即使HTTP为200，也必须检查 [`status`](../src/api/sku_schemas.py:18)、[`sku_count`](../src/api/sku_schemas.py:28)和[`warnings`](../src/api/sku_schemas.py:26)。交易模型现支持已验证的规格名称；该路径按用户要求不提取图片，保留兼容响应中的空主图字段。旧重量表路径的元数据图片行为不变。

## 8. 配置和部署

### 8.1 独立并发及超时

配置在[服务器设置](../src/api/config.py)中读取；不配置时使用默认值。

| 环境变量 | 默认值 | 规则 |
|---|---|---|
| SKU_MAX_CONCURRENCY | 2 | 每进程1至8个查询；与图搜工作线程独立 |
| SKU_HTTP_TIMEOUT | 20 | 每次上游请求超时秒数，大于0且不超过120 |
| SKU_QUERY_TIMEOUT_SECONDS | 90 | HTTP查询等待秒数，有限正数 |

- 固定最多一次网络重试，最多两次受限重定向，因此总耗时可能超过单次请求超时。
- 使用专用线程池执行同步网络操作；准入包含Cookie加载阶段，满额立即拒绝，不建立无界队列。
- 客户端断开或HTTP等待超时不能杀死同步线程。操作继续占槽，直到真实结束并关闭会话。不能以取消请求绕过并发限制。
- 正常停机先停止准入，等待已接收操作完成后关闭线程池。反向代理读取超时建议高于查询等待超时，例如默认配置下110秒。
- 限制按进程计算；[现有启动入口](../src/run_api.py:23)使用单进程。自行增加进程数会倍增总并发。

### 8.2 同步后必须重启

1. 将实现、测试及文档通过正常发布流程同步到服务器，确保依赖满足[项目依赖清单](../requirements.txt)。
2. 保留现有数据库路径、Cookie加密密钥及搜索密钥；无需新建表或再次上传已有可用Cookie。
3. **git同步代码后必须重启实际API服务进程，路由才会注册。只同步文件不会让运行中的服务自动增加接口。** 使用现有进程管理器重启原服务；手动启动时先停止原进程，再通过Python运行[启动入口](../src/run_api.py)。不要另起重复占用端口的进程。
4. 确认反向代理允许新路径POST，读取超时符合上述配置。重启后在站点 /docs 或 /openapi.json 确认出现 /api/v1/product-skus。
5. 由用户使用第7节本地密钥示例发起实际查询，并区分SKU数据、风控、登录和数据源不适用结果。

本轮没有执行git提交、推送、服务器部署或重启，也没有请求上述线上网站或1688商品。

## 10. 2026-09-17 本机解析修复与在线验证

此前章节中的未在线验证记录为首期历史状态，本节记录本轮结果。

### 根因及修复

- 普通函数体大括号被误当 JSON，首次失败即停止，导致后续业务参数未扫描。现跳过完整函数体而不执行代码；未知词法形式保守拒绝。
- 完整业务对象含未加引号的数字属性键。仅在解码器明确期待属性名的位置规范安全整数键，最多256次；随后仍要求整个外层对象成功解码、拒绝重复键，不从破损对象内部打捞 SKU。
- SKU 归属使用固定全局业务结构，要求参数、商品详情、交易模型三处商品身份与请求一致；推荐分支继续排除，普通匿名列表不继承身份。
- 原目标重量表只含包装尺寸和重量，并非 SKU 数据。新增已验证交易列表来源，逐行使用规格定义的顺序、名称和值集合核验规格属性，拒绝不匹配或歧义，不生成笛卡尔积，不对页面或规格值整体反转义。
- 未增加依赖、浏览器或网页执行能力。按用户最终要求，新交易来源不提取、不下载图片。
