# 独立1688 SKU模块使用说明

## 1. 范围

输入标准1688详情链接及已有Cookie文件，请求详情HTML，输出商品ID、SKU ID、规格位置和值、规格名、商品主图及状态。

- 不修改图搜、API和数据库，不调用MTOP，不启用浏览器兜底。
- 不自动寻找Cookie文件；只读取明确传入的路径。
- 没有真实Cookie，不代表已成功在线采集。目标商品772946834568仍待实测。
- 规格名目前始终为空并告警：尚无已验证真实规格定义路径，不推断颜色、尺码。
- 主图仅接受唯一且绑定当前商品地址的Open Graph元数据。此规则只经过合成样例测试，未确认目标页面提供这些元数据。

## 3. 运行

在项目根目录、已安装[项目依赖](../requirements.txt)的Python环境执行。PowerShell中先将控制台输出编码和Python UTF-8模式设为UTF-8。

调用格式：python ＋ [命令行入口](../src/fetch_1688_sku.py) ＋以下参数。

| 参数 | 用法 |
|---|---|
| --url | 必填，例如 "https://detail.1688.com/offer/772946834568.html" |
| --cookie-file | 必填，已有Cookie文件的实际路径；建议加双引号 |
| --output | 可选，结果JSON文件路径；省略则输出到控制台。父目录须存在，会覆盖已有文件，不可与Cookie文件相同 |
| --timeout | 每次请求超时秒数，默认20，范围大于0且不超过120 |
| --retries | 网络失败和临时服务错误重试次数，默认1，允许0至2 |
| --help | 查看参数说明，不采集 |

支持标准HTTP输入，统一规范化为HTTPS；删除查询参数与片段。只接受详情域名和数字商品路径，拒绝用户信息、显式端口和非详情路径。

Cookie格式沿用[现有加载器](../src/image_search/cookies.py)：导出的记录数组、包装对象、名称到值映射或Cookie头文本。推荐记录数组，避免丢失路径、有效期与安全属性。不要求MTOP Token。过期或不适用域的记录会被过滤，路径和安全属性交给CookieJar匹配；无可用记录则初始化失败。

## 4. 结果与退出码

[结果结构](../src/product_sku/models.py:23)包含商品ID、规范链接、来源、状态、原因、主图、SKU数组、数量、警告和完整性。SKU ID使用字符串。规格保留数字位置和原始字段；例如第一、第三位置有值时，第二位置仍保留为空。

| 状态 | 含义 | 退出码 |
|---|---|---|
| partial_success | 至少有一条有效SKU；缺少可靠规格名、主图或完整性证明 | 0 |
| success | 预留完整成功状态；当前解析器不返回，不承诺全部SKU | 0 |
| access_restricted | 风控挑战、403、429或禁止的重定向 | 1 |
| login_required | 登录跳转、明确登录表单或401 | 1 |
| source_not_applicable | 当前商品字段缺失或空数组，由原因字段区分 | 1 |
| parse_failed | 格式错误、归属不明、无有效SKU、超出限制等 | 1 |
| network_failed | 有限重试耗尽或异常HTTP状态 | 1 |
| 参数、初始化、内部错误或输出失败 | 标准错误仅输出固定说明，不输出异常原文 | 2 |

有效SKU必须同时包含有效ID与至少一个非空字符串规格值。拒绝浮点、布尔ID；重复一致记录合并，同一ID规格冲突时移除该ID并告警。不会根据SKU顺序推断规格名称或颜色图。

## 5. 解析边界

- 只解码脚本中的完整JSON对象、数组或JSON字符串，不执行脚本，不做整页反转义。非JSON的JavaScript对象及单引号字符串不保证支持。
- 使用明确商品身份字段建立归属；排除推荐分支、外商品；匿名列表及不明确实体不继承归属。不以页面URL直接认定所有数组属于当前商品。
- 拒绝重复JSON键。无法验证归属时宁可报告失败，不盲目收集整页SKU。
- 上限：响应4 MiB，结构深度32，JSON候选256，节点/行100000，规格位置32。解码后的文本也受大小限制。
- 手工最多两次重定向，仅允许同商品HTTPS规范详情地址；不会请求登录域、外域或挑战地址。
- 默认每次请求20秒，最多一次网络重试。429、403和已识别访问限制不重试。
- 每次响应均关闭，自建会话关闭；借入会话不关闭。借入会话必须是专用干净会话，客户端会替换其CookieJar，不适合借用正在使用的图搜会话。
- 默认自建会话使用Chrome模拟，不继承图搜来源头，禁用环境代理继承。Chrome模拟不保证与Cookie来源浏览器完全一致。
- UTF-8优先；仅在响应头明确指定GBK/GB2312时尝试相应兼容解码，不静默替换乱码。
- 不保存整页、Cookie、签名或异常原文；风险跳转参数不会进入结果。
